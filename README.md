# AI 个人记忆库

跨 AI、跨电脑的个人记忆共享仓库。换任何 AI、换任何电脑，先让它读这个仓库，就能接上我的背景和项目进度，不用重新自我介绍。

- GitHub 仓库：`roninzhitongcai-lab/ronin-ai-local-memory`（私有）
  - 说明：GitHub 仓库名只能用英文/数字/连字符，所以仓库 slug 用英文，库的中文名就是「AI 个人记忆库」。
- 本地目录：`~/workspace/ai-personal-memory/`（在 Muse 的电脑上）；在自己的电脑上 clone 到任意固定位置即可，建议就叫 `ai-personal-memory`。

---

## 第一部分：写给自己（Cai）

### 文件夹结构

```
ai-personal-memory/
├── README.md      本说明
├── USER.md        我是谁：身份、长期目标、语气和偏好
├── SOUL.md        协作规则：怎么和我干活、红线、变更记录
├── AGENTS.md      给 AI 的操作手册：目录、任务优先级、协作规矩
├── inbox/         临时想法和未整理的东西，先扔这里
├── projects/      长期项目，一项目一文件（现状+下一步）
├── tasks/         任务笔记，一任务一文件（用模板建）
├── reviews/       周复盘 / 月复盘
├── knowledge/     可复用经验：文案规范、拍摄手法、竞品观察
├── templates/     模板（任务笔记、周复盘）
└── archive/       已结束的东西，只读
```

### 怎么用

1. **换 AI 时**：把仓库链接（或 clone 下来的文件夹）给新 AI，让它按顺序读 `USER.md → SOUL.md → AGENTS.md → 对应 projects/*.md`。
2. **换电脑时**：`git clone` 这个私有仓库即可，全部记忆都在里面。
3. **日常**：任务做完让 AI 更新 `tasks/` 笔记并 push；新规则让 AI 追加进 `SOUL.md` 并留变更记录。
4. **安全**：仓库保持 Private。银行卡、密码、API 密钥、验证码永远不要往这里放——需要保管的密钥用密码管理器，不要用 Git 仓库。

### 同步方式

- 在 Muse 里：直接跟 Roni 说「同步记忆库」，它会把本地目录推送到这个仓库并回读验证。
- 在自己电脑上：`git pull` 拉最新，改完 `git add . && git commit -m "说明" && git push`。

## 第二部分：写给 AI

你正在读的是 Cai 的个人记忆库。规则如下：

1. **开工前必读顺序**：`USER.md` → `SOUL.md` → `AGENTS.md` → 本次任务对应的 `projects/*.md` 和 `tasks/*.md`。没读完不要开始产出。
2. **读写权限**：
   - 可读：全库。
   - 可写：`inbox/`、`tasks/`、`reviews/`、`projects/`、`knowledge/` 里新建和更新；`SOUL.md` 只能追加新规则并写变更记录。
   - 禁止修改：`templates/` 原文、`archive/`、以及任何标注「已确认」的内容（先提出、经 Cai 确认再改）。删除任何文件前必须先问 Cai。
3. **任务优先级**：见 `AGENTS.md` 第 3 节的对照表，按任务类型先读对应文件。
4. **收尾义务**：完成任务后更新任务笔记（带时间戳的进展记录）、相关项目文件的「下一步」，有新协作规则时追加到 `SOUL.md`，然后提醒 Cai 同步/推送。
5. **安全红线**：不要把银行卡、密码、API 密钥、验证码等敏感信息写入本库任何文件；如果 Cai 误发，先提醒再处理，不要落盘。
6. **冲突处理**：本库规则与 Cai 当场指令冲突时，以当场指令为准，但要在任务笔记里记下这次例外；与安全红线冲突时，先确认再执行。
